# 권한별 알림

백엔드 Kotlin + DB 알림함, 프론트 30초 폴링으로 동작합니다. 별도의 외부 서비스나 API 키는 필요하지 않습니다.

## 수신 정책

- 예산 신청: 같은 모임의 OWNER / OPERATOR. 신청자 본인은 제외합니다.
- 승인 / 반려: 해당 신청자에게 결과 알림을 생성합니다.
- 새 멤버 참여: 해당 모임 OWNER / OPERATOR. 참여자 본인은 제외합니다.
- 생성 시점의 권한으로 수신자를 결정합니다. 생성 후 권한이 바뀌어도 기존 알림을 재분배하지 않습니다.
- 현재 모임 멤버인 경우에만 과거 알림 목록, 안 읽은 개수, 읽음 처리를 사용할 수 있습니다. 탈퇴 / 강퇴되면 해당 모임 알림은 표시하지 않습니다.

## API

- GET /notifications?page=0&size=20: 본인 알림 최신순 Slice 조회. page 0~10000, size 1~50. 다음 페이지가 없으면 nextPage=null.
- GET /notifications/unread-count: 본인의 현재 소속 모임 안 읽은 알림 개수.
- PATCH /notifications/{id}/read: 본인 알림이고 현재 모임 멤버인 경우 읽음 처리. 이미 읽은 알림은 기존 시각을 유지합니다. 성공 204.
- 사용자 ID는 요청 파라미터가 아닌 인증 사용자에서 가져옵니다. 다른 수신자의 알림은 404로 처리합니다.

## 트랜잭션과 저장

NotificationService의 생성 메서드는 Propagation.MANDATORY를 사용합니다. 신청 / 승인 / 반려 / 모임 참여 트랜잭션에 함께 참여하므로 비즈니스 처리 실패 시 알림도 롤백됩니다. 신청 등록에 @Transactional을 추가했습니다. 별도의 비동기 전송이나 외부 네트워크 호출은 없습니다.

notification 테이블과 recipient_id,id 및 recipient_id,read_at 인덱스를 추가합니다. 개발환경 ddl-auto:update로 생성되며 운영환경에서는 테이블 / FK / 인덱스 배포가 필요합니다. 사용자 또는 모임 삭제 시 관련 알림은 DB FK ON DELETE CASCADE로 삭제됩니다.

## 화면

내 모임 헤더와 모임 작업 화면 우측 상단에 종 아이콘을 제공합니다. 안 읽은 개수는 30초마다 갱신하며 백그라운드 탭은 폴링을 쉬고 다시 활성화될 때 개수를 갱신합니다. 알림함이 열려 있을 때 목록도 30초 간격으로 갱신합니다. Escape / 바깥 클릭으로 닫을 수 있습니다.

알림을 누르면 읽음 처리 후 예산 신청 목록 또는 멤버 목록으로 이동합니다. 개별 신청 상세 링크나 SSE 실시간 전송은 이번 범위에 포함하지 않습니다. 업무 요청은 동일 화면에서 토스트로 즉시 확인하고 알림함에는 다음 조회 주기에 반영됩니다.

## 검증

NotificationIntegrationTest에서 수신 역할 / 모임 분리 / 본인 제외 / 신청 결과 / 중복 처리 실패 / 참여 / DB 롤백 / 읽음 권한 / 탈퇴 후 접근 / 페이지 제한 / 인증 / 트랜잭션 강제를 검증합니다. H2 테스트는 DB 동작 검증용이며 동시 읽음의 최초 시각 보장, 다중 서버 폴링 부하, MySQL 부하 수치는 별도 검증 대상입니다.
